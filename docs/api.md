# SilverAI API

The FastAPI service exposes the XAG/USD spot terminal and prediction contract. Start it from the repository root:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

The backend loads `.env` when present. Without `SILVERAI_DATA_MODE`, it starts in `historical` mode. Set `SILVERAI_DATA_MODE=live` only when the live bridge and its provider are configured.

## Market and model endpoints

| Method and path | Description |
| --- | --- |
| `GET /api/health` | Reports service/model availability, provider status, and prediction database path. |
| `GET /api/models` | Reports the 34-feature order, selected 60-minute horizon, calibration status, holdout status, and research-artifact status. |
| `GET /api/market/candles?limit=288&timeframe_minutes=5` | Returns real XAG/USD OHLC candles from the Dukascopy files. Supported timeframes are 5, 10, 15, and 30 minutes; `limit` is 24–2500. |
| `GET /api/market/status` | Reports whether the configured source is historical or live, including freshness and companion availability in live mode. |
| `GET /api/provider/health` | Alias for the configured provider status. |
| `GET /api/live/status` | Reports live-provider and live-log freshness for the explicit live-mode UI. |
| `GET /api/market/insights` | Returns causal trend, volatility, session, data-quality, and cross-market context. |

Historical candles include `data_status: historical`, `source`, `timezone: UTC`, and session statistics. The source contains bid OHLC only; volume is unavailable, is not a model feature, and is not returned by the API. In live mode, the 5-minute response can include accepted live candles and reports `data_status: live`, but freshness must still be checked.

## Prediction endpoints

`POST /api/predict` accepts one observation containing the ordered 34 spot features. `POST /api/predict/batch` accepts an `observations` array. The feature order is authoritative in [`src/features/spot_features.py`](../src/features/spot_features.py). Inputs must be generated by the shared feature pipeline and must represent a closed candle.

Responses include binary Up/Down probabilities, calibrated probabilities when available, confidence, model metadata, and one of `UP`, `DOWN`, or `NO_CLEAR_SIGNAL`. A signal below the configured confidence threshold becomes `NO_CLEAR_SIGNAL` and `trade_decision: WAIT`.

`POST /api/predict/confirmed` accepts:

```json
{
  "timestamp": "2026-11-13T21:55:00+00:00",
  "close": 31.25,
  "features": {
    "timestamp": "2026-11-13T21:55:00+00:00",
    "known_at": "2026-11-13T22:00:00+00:00"
  }
}
```

The example is schematic: `features` must also contain every required feature field. This endpoint is the persistence boundary for a finalized candle and stores the forecast for later outcome evaluation.

## Persistence, evaluation, and paper routes

| Method and path | Description |
| --- | --- |
| `GET /api/predictions/latest` | Returns the latest persisted finalized signal, or an explicit no-signal reason. |
| `GET /api/predictions?outcome_status=pending&limit=100` | Lists persisted forecasts, optionally filtered by outcome status. |
| `POST /api/predictions/evaluate` | Replays configured historical candles to settle eligible stored forecasts. |
| `GET /api/evaluation/metrics` | Returns stored outcome metrics plus versioned report metrics when available. |
| `GET /api/paper-trading` | Returns analytical paper-trading state and configured cost assumptions. |
| `POST /api/paper-trading/start` | Starts paper trading only when a fresh live feed is available. |
| `POST /api/paper-trading/stop` | Stops the paper-trading session. |
| `POST /api/paper-trading/reset` | Resets paper-trading state. |
| `POST /api/testing/clear` | Clears testing predictions/outcomes and live-testing logs without deleting models or historical data. |
| `GET /api/diagnostics` | Returns non-fatal inference, persistence, and live-feed diagnostics. |
| `GET /api/evaluation/frozen` | Reads the frozen-evaluation manifest if one exists. |
| `POST /api/evaluation/frozen` | Creates a frozen manifest only when a genuine live provider is available. |

Rows with missing or gapped future candles remain `pending`; the service does not guess outcomes. Paper-trading routes are analytical and do not place orders.

## Live bridge routes

The Node bridge sends normalized closed one-minute candles to `POST /api/live/candles` and connection state to `POST /api/live/heartbeat`. The backend builds complete five-minute candles, rejects forming/duplicate data as appropriate, requires XAG/USD, XAU/USD, and EUR/USD companions for new scoring, and applies the configured 180-second stale window.

See [`docs/spot_live_source.md`](spot_live_source.md) for the provider contract and verification gate.
